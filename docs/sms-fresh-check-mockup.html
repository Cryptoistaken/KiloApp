Silent retry, capped

The user sees a fresh number, or a plain failure. A number that does not pass fades out and is never written to My numbers, so it costs a provider slot but leaves no trace on the list.

The tally lives on the Activity page

Checked, Fresh and Skipped are running totals, not per-run state, so they join the existing tile rows on the dedicated analysis page. Nothing about the current run clutters the list.

When every try fails

The same error surface as today, with the count added: No fresh numbers found after checking 5 numbers for 229016XXX

When the check itself cannot run

A failed check is not a pass. The number is treated as unknown and the run stops, matching the bot's checkerDown behaviour, rather than handing back a number nobody verified.

Where the tally lives

Not on the SMS tab. The Activity page already summarises runs, so the check counts join it as a third row of tiles, in the same shape as the two rows above them.

Same page, same tiles

The Activity page is reached by swiping the analysis tiles on the main tab, or tapping Today analysis. It keeps its own top bar and its existing two rows, so the new row reads as part of the page rather than an addition bolted on.

Why here and not the list

The SMS tab answers "what do I have right now". These three answer "how has the checking been going", which is history, and history already has a page. It also keeps the tab itself unchanged for anyone who never types the C.

What the three mean

Checked is every number that went through the probe, Fresh is how many came back clean and were kept, and Skipped is the remainder that did not. The three always sum to Checked.

Counted per session, not per run

They accumulate like the other tiles on this page, which are all lifetime totals for the stored numbers. They are not reset per generate, so a single run never has its own counter on screen.

Swipe a row to generate again

A row already knows its range, so a swipe in either direction re-runs that same range instead of asking again. Right and left both generate, and a fresh row re-checks on the way.

Drag either way. The label is the same both sides, so there is no wrong direction to learn.

Which range gets used

The row's own range, which is already stored on SmsNum and used by today's Regenerate action. No new field.

Does it check again

Yes, if the row was fresh. The check is part of what the row means, so re-generating an unchecked row stays unchecked and re-generating a fresh one checks again. A plain swipe on a row that never asked for a check does not start one.

Which direction

Both do the same thing, so the gesture has one meaning. This replaces the current left-swipe Regenerate, which today sits opposite a right-swipe that opens the sheet.

The checkbox follows the range

Delete the C and the box empties by itself. Clicking the box does the reverse. Type in the field or tap the checkbox, the two stay in step either way.
